# MashiroBot 零基础财报与招股书课程插件设计

## 1. 目标

在 MashiroBot 的 `plan` 插件系统中新增独立的财报学习插件，每天 12:20
通过微信发送一张适合零基础用户阅读的财报学习卡，并在每周二、周五 18:10
发送招股书学习卡。首期包含 30 天财报课程和 4 周 8 节招股书课程，帮助用户
逐步理解公司如何赚钱、三张主要报表、经营变化、上市过程和常见风险。

课程不是投资荐股工具。插件不预测股价、不建议买卖，也不承诺通过阅读财报
获得投资收益。

## 2. 已确认的用户体验

- 首期采用预制 30 天课程，不在每天发送前临时生成课程正文。
- 每天 12:20 发送。
- 消息形式为微信文字学习卡，附指定年报页码和官方 PDF 链接，不发送完整 PDF。
- 课程按日推进，是否答题不阻塞下一课。
- 漏掉的课程不自动堆积，可使用 `补学第N天` 单独获取。
- 回答格式为 `财报答案……`，由 OpenClaw 网关发起聊天模式对话生成个性化
  点评并记录进度。
- 发送失败时仅在当天补发；跨天不补发旧课程。
- 插件安装完成后的下一自然日为课程第 1 天。
- 招股书课程从安装后的首个周二开始，每周二、周五 18:10 发送。
- 首期招股书使用农夫山泉、泡泡玛特、小米集团和京东物流的港交所中文
  招股书，每家公司连续学习两节。
- 第 8 节招股书课程完成后停止自动推送，并提示用户后续添加下一批课程。

## 3. 课程结构

### 3.1 财报课程

| 天数 | 内容 |
| --- | --- |
| 第 1 天 | 年报地图：年报结构、审计报告、利润表、资产负债表和现金流量表 |
| 第 2～8 天 | 伊利股份：消费品业务、收入、毛利率、渠道、存货和现金流 |
| 第 9～15 天 | 美的集团：制造业、成本结构、海外收入、资产投入和现金流 |
| 第 16～22 天 | 顺丰控股：物流收入、履约成本、重资产投入、负债和经营效率 |
| 第 23～29 天 | 腾讯控股：业务分部、平台收入、投资资产、研发和现金流 |
| 第 30 天 | 横向比较四家公司，完成一份零基础公司分析 |

每课控制在约 10～15 分钟。每天只引入少量新术语；首次出现的术语必须使用
普通语言解释，并说明它在当前公司的具体含义。

### 3.2 招股书课程

招股书课程每周学习一家公司，周二和周五分别拆解同一份招股书：

| 周次 | 公司 | 周二课程 | 周五课程 |
| --- | --- | --- | --- |
| 第 1 周 | 农夫山泉 | 公司、行业和商业模式 | 财务数据、风险和募集资金用途 |
| 第 2 周 | 泡泡玛特 | IP 模式、产品和销售渠道 | 存货、门店效率和主要风险 |
| 第 3 周 | 小米集团 | 硬件、互联网服务和生态模式 | 利润结构、风险和上市融资 |
| 第 4 周 | 京东物流 | 物流网络、客户和规模效应 | 成本、资产投入、亏损和风险 |

每节招股书课程同样控制在约 10～15 分钟。第 8 节发送后课程结束，不自动
抓取或选择下一家公司。

## 4. 学习卡格式

财报和招股书学习卡都按固定顺序输出：

1. 第几天、公司名称和今日主题。
2. 今日学习目标。
3. 需要阅读的年报章节和 PDF 页码。
4. 关键原文或关键数字。
5. 面向零基础的中文解释。
6. 一个常见误读或需要警惕的问题。
7. 一道可用自然语言回答的小问题。
8. 报告或招股书名称、报告期和官方 PDF 链接。

所有数字必须同时标明报告期、单位、年报页码和来源。课程内容必须明确区分：

- 财报披露的原始事实；
- 课程作者的通俗解释；
- 需要用户进一步判断的问题。

## 5. 财报来源与课程数据

- 伊利股份、美的集团和顺丰控股只使用巨潮资讯网或对应交易所披露的
  2025 年完整年报。
- 腾讯控股只使用港交所披露易或腾讯投资者关系页面发布的 2025 年完整年报。
- 农夫山泉、泡泡玛特、小米集团和京东物流只使用港交所披露易发布的中文
  招股书。
- 课程制作阶段要核对报告版本、报告期、PDF 页码、单位和关键数字。
- 官方链接失效时不得静默换用财经媒体或二次转载；该课进入来源异常状态并
  记录维护错误。

课程保存在插件内的版本化数据文件中。每课至少包含：

- 课程类型和该类型内唯一课程序号；
- 公司、主题和预计阅读时间；
- 学习卡正文；
- 提问和参考要点；
- 报告名称、报告期、官方 URL、页码和单位；
- 课程数据版本。

课程不在运行时抓取网页，也不依赖财经媒体摘要，因此 12:20 的日常发送只
依赖本地课程数据和微信机器人。

## 6. 插件边界

新增独立目录：

```text
plan/plugin/mashirobot-plugin-financial-report/
```

插件 ID 为 `mashirobot-plugin-financial-report`，固定菜单编号为 **5**。
插件遵守现有同步接口契约，导出 `match`、`handle`、`healthCheck` 和
`getHelp`。不修改现有计划、游戏计时、状态和战利品插件的业务行为。

插件内部按职责拆分：

- 路由层：只负责识别微信指令和组装标准插件结果。
- 课程层：读取并校验 30 天课程数据。
- 状态层：访问插件自己的 SQLite 表。
- 点评层：创建后台聊天点评任务，不在同步微信请求中等待模型完成。
- Windows worker：负责定时发送、当天重试和待点评任务重试。
- 安装与健康检查：负责数据库迁移、计划任务注册、路径和依赖验证。

## 7. 微信指令

| 指令 | 行为 |
| --- | --- |
| `财报课程` | 查看课程日期范围、今天的课、已发送数、已回答数和暂停状态 |
| `今日财报` | 重新显示当天课程；该手动操作不改变自动发送幂等状态 |
| `补学第N天` | 获取第 N 天课程，N 必须在 1～30 |
| `财报答案 内容` | 默认回答最近一次发送且尚未回答的课程 |
| `财报答案 第N天 内容` | 明确回答第 N 天课程，适用于补学 |
| `招股书课程` | 查看 8 节招股书课程的当前进度和完成状态 |
| `今日招股书` | 在招股书课程日重新显示当天学习卡 |
| `补学招股书第N课` | 获取第 N 节招股书课程，N 必须在 1～8 |
| `招股书答案 内容` | 默认回答最近一次发送且尚未回答的招股书课程 |
| `招股书答案 第N课 内容` | 明确回答第 N 节招股书课程 |
| `暂停财报` | 暂停自动推送并冻结课程日历 |
| `继续财报` | 从暂停前的下一课程日继续，不补发暂停期间内容 |
| `重学今日财报` | 重新发送今日课程并允许新增一次回答尝试 |

如果无法判断 `财报答案` 对应哪一课，插件返回明确提示，要求使用
`财报答案 第N天 内容`，不得猜测关联课程。

如果无法判断 `招股书答案` 对应哪一课，同样要求使用
`招股书答案 第N课 内容`。暂停和继续同时作用于财报与招股书自动推送，
手动补学不受暂停限制。

## 8. 课程日历与暂停规则

安装完成后的下一自然日是第 1 个课程日。正常运行时，每经过一个未暂停的
自然日，课程序号前进一天，与是否阅读或答题无关。

- 当天 12:20 后首次成功发送即记录为已发送。
- 当天始终未能发送则记录为错过；次日进入下一课，不补发旧课。
- 用户可以通过 `补学第N天` 获取任何已开始或错过的课程。
- 暂停期间不计算课程日；继续后从暂停前的下一序号恢复。
- 第 30 天发送后课程进入已完成状态，不再自动发送。

招股书课程使用独立进度：

- 安装后的首个周二是第 1 节，随后按周二、周五依次推进到第 8 节。
- 当次 18:10 后成功发送即记录为已发送；整天失败则记录为错过，并在下一
  个计划日进入下一节。
- 错过的课程只通过 `补学招股书第N课` 获取，不自动堆积。
- 暂停期间不计算课程日；继续后从暂停前的下一节恢复。
- 第 8 节发送后停止招股书任务的有效推送，并发送一次课程完成提示。

## 9. 自动发送与幂等

注册两个当前用户范围的 Windows 计划任务：

- 财报任务每天 12:20 启动；
- 招股书任务每周二、周五 18:10 启动。

两个任务都在各自发送日以 15 分钟间隔重复检查并启用
`StartWhenAvailable`，电脑在计划时间后才开机时可在当天立即补发。

worker 每次运行都先读取 Asia/Shanghai 当前日期、课程状态和当天发送记录：

1. 尚未到对应计划时间、课程暂停或对应课程已完成时不发送。
2. 当天已发送成功时直接退出。
3. 当天尚未发送时调用现有 OpenClaw 微信发送入口。
4. 只有收到明确发送成功结果后才写入成功状态。
5. 失败保留错误和尝试时间，下一次 15 分钟检查继续尝试。
6. 日期跨天后不再发送上一课程日的内容。

数据库唯一约束保证同一账号、会话、课程日和发送日期只有一条成功记录。
计划任务重复触发、微信重试或 worker 重启都不得产生重复自动消息。

## 10. 聊天模式个性化点评

微信同步请求只完成以下动作：

1. 校验课程和回答内容；
2. 保存一次回答尝试，状态为 `pending`；
3. 启动或唤醒后台点评 worker；
4. 立即回复“已收到，正在生成点评”。

后台 worker 对财报答案和招股书答案使用同一点评管线，通过现有 OpenClaw
Gateway 的 `openclaw agent` 命令发起一次
聊天式模型调用，并使用财报插件专属的会话键。该调用必须符合 ChatGPT
“聊天”模式的用途：解释知识、回应用户答案和继续学习对话；不得创建工作
模式任务、Codex 工作区、持久目标或交付物。

实现中明确禁止使用 Codex CLI、Paseo agent、工作模式或 Codex goal 生成点评。
调用不直接投递微信消息；worker 读取 JSON 结果、校验点评文本、保存数据库，
再通过现有 OpenClaw 微信发送入口投递。

提示词只包含：

- 当天学习卡；
- 课程参考要点；
- 用户本次回答；
- 固定点评格式和安全约束。

聊天点评控制在约 300～500 个中文字，固定包含：

1. 理解正确之处；
2. 遗漏或混淆之处；
3. 一个应回到年报核对的数字或句子；
4. 下次阅读的具体注意点。

点评不得评价用户人格、不得推荐股票、不得预测收益，也不得把课程外信息
伪装成财报事实。点评成功后保存文本和完成时间，再通过微信发送。聊天模型
暂时不可用时保留 `pending` 状态并由后台重试，不丢失用户回答。

同一课可以提交多次回答；每次作为独立尝试保存，不覆盖历史点评。

## 11. SQLite 状态

使用现有正式 SQLite 数据库，但只新增带 `financial_report_` 前缀的表：

- 课程状态：账号、会话、课程类型、开始日期、暂停区间和完成状态；
- 发送记录：课程类型、课程序号、计划发送日期、状态、尝试次数和错误；
- 回答记录：课程类型、课程序号、回答正文、提交时间和点评状态；
- 点评记录：回答尝试、聊天模型输出、发送状态、重试次数和错误。

正式迁移前必须执行 WAL checkpoint、完整性检查和可恢复备份。不得清空、
重建或覆盖现有数据库，也不得修改其他插件的表。

## 12. 错误处理

- 课程数据校验失败：插件健康检查失败，不注册或启用自动任务。
- 官方来源缺失：对应课程不发送替代内容，记录来源异常。
- 微信发送失败：对应课程日每 15 分钟重试，跨天停止。
- 聊天点评失败：保留回答，后台有限退避重试，并允许健康检查显示积压。
- 数据库写入失败：不宣称发送或点评成功，记录结构化日志。
- 重复进程：通过数据库状态和任务单实例策略共同防重。
- 路径、Node、PowerShell 或 OpenClaw Gateway/CLI 入口不可用：健康检查明确
  列出缺失项，不使用 Codex 工作模式作为降级。

日志沿用 `%USERPROFILE%\.openclaw\logs\mashirobot.log`，每条日志包含
插件 ID、事件、课程日和简短错误，不写入完整用户回答或聊天提示词上下文。

## 13. 测试与验收

### 自动测试

- 清单、目录、同步导出和菜单编号 5 的加载测试。
- 指令匹配、范围校验、默认答案关联和歧义提示测试。
- 30 天财报课程及 8 节招股书课程的数据结构、URL、页码、单位和必填字段
  校验。
- 课程日期推进、暂停、继续、错过和第 30 天结束测试。
- 招股书周二/周五推进、错过、补学和第 8 节结束测试。
- 12:20、18:10 边界、Asia/Shanghai 日期和跨天不补发测试。
- 重复任务、重复 worker 和重复微信重试的幂等测试。
- 聊天调用参数、专属会话键、pending、成功、失败、重试和多次回答测试；
  测试必须断言没有调用 Codex CLI、Paseo agent、工作模式或持久目标。
- SQLite 迁移、备份、完整性和其他插件数据保持不变测试。
- 现有系统级插件加载、路由、帮助和 README 边界回归测试。

### 真实验收

完成实现后必须取得以下证据：

1. 新插件以菜单编号 5 加载，现有四个插件仍正常。
2. 测试时间分别触发一次真实财报卡和招股书卡，并核对文字、页码和官方
   链接。
3. 重复运行发送 worker，微信没有出现第二条自动消息。
4. 模拟发送失败后在当天恢复，学习卡成功补发。
5. 从微信分别发送 `财报答案……` 和 `招股书答案……`，收到接收确认和
   后续聊天模式点评，并从调用记录确认没有创建工作模式任务。
6. SQLite 中存在对应发送、回答和点评记录。
7. 暂停、继续、财报补学、招股书补学和两类课程进度查询均从微信验证。
8. 四份官方年报和四份中文招股书分别抽样核对至少两个课程数字和页码。

本地单元测试通过、文件存在或计划任务显示 Ready 都不能单独证明完成；必须
完成上述微信端到端验证。

## 14. 明确不做的内容

首期不包含：

- 股票买卖建议、估值目标价或收益预测；
- 每天动态选择新发布财报；
- 自动网页抓取或自动更新到 2026 年报告；
- 首期结束后自动寻找或生成下一批招股书课程；
- 群聊多人课程排行榜；
- 图片学习卡或完整 PDF 微信附件；
- 公网服务、账号系统或跨设备同步。

这些能力如有需要，后续作为独立设计扩展，不进入首期范围。
