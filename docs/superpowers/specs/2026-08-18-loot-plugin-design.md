# 「战利品」插件替换旧笔记功能设计

## 目标

完整删除现有 `mashirobot-plugin-note` 笔记功能，以新的独立插件 `mashirobot-plugin-loot` 替代菜单位置。新插件显示名称为「战利品」，只负责通过微信记录当天最后一次发送的「爽点」、在晚间催促缺失记录，并在次日上午原样回放前一天的记录。

新功能不承担通用笔记、任务管理、积分、等级、排行榜、AI 总结或固定学习分类。

## 插件边界

- 新插件目录为 `plan/plugin/mashirobot-plugin-loot`，保持独立的清单、入口、存储、Windows worker、安装器、帮助和测试。
- 固定使用旧笔记插件释放的 `menuIndex: 4`，不改变其他插件的菜单编号。
- 微信发送复用 MashiroBot 已有 OpenClaw 微信账号、目标和发送方式，不新增第三方通知通道。
- 计划插件继续负责计划、作息和其他提醒；「战利品」插件不修改其数据库模型和业务路由。

## 微信记录

唯一业务关键词为首行精确匹配的 `爽点`。有效消息格式为：

```text
爽点
今天读完了一个章节，终于听懂了关键对话。
还解决了一个拖了很久的问题。
```

规则：

- `爽点` 后必须有非空正文；去除正文首尾空白，保留内部换行。
- 正文内容和分类完全自由，每天可以变化，不提供英语阅读、听力、对话等固定模板。
- 同一上海自然日可以发送多次；每次有效发送整体覆盖当天旧内容，当天只保留最后一次。
- 单独发送 `爽点` 时只提示补充内容，不写入空记录，也不停止当晚提醒。
- 保存成功后回复简短确认，并使当天后续定时检查不再发送提醒。
- `/战利品` 和 `/战利品详细` 只显示记录格式、覆盖规则和提醒时间，不恢复通用笔记命令。

## 定时行为

所有日期判断使用 `Asia/Shanghai`。

### 晚间收集

- 每天 21:00、21:10、21:20、21:30、21:40、21:50 和 22:00 运行一次检查。
- 若当天已有有效「爽点」，该次检查静默结束。
- 若当天尚无有效记录，发送简短微信提醒，请用户先记录今天的爽点。
- 22:00 是最后一次提醒；22:00 后不再催促，不影响 22:10 左右睡觉的目标。
- worker 必须根据数据库当前状态幂等判断，不能依赖常驻内存或仅在首次提醒时创建的临时状态。

### 次日回放

- 每天 10:00 查询前一个上海自然日的最终记录。
- 前一天没有记录时静默结束，不发送空提醒。
- 有记录时发送固定前缀、日期和原始正文，不改写、不评分、不总结：

```text
与其整天沉醉于别人的故事，不如自己安心多学一些，也留下点自己的故事。

2026年8月18日的爽点：
今天读完了一个章节，终于听懂了关键对话。
还解决了一个拖了很久的问题。
```

## 数据模型

正式数据继续保存在 `plan/sqlite/openclaw-planner.sqlite`。新增表只保存每天最后一次记录：

```sql
CREATE TABLE loot_entries (
  entry_date TEXT PRIMARY KEY,
  content TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

- `entry_date` 为上海日期 `YYYY-MM-DD`。
- 写入使用 upsert；首次写入同时设置创建和更新时间，覆盖时只更新正文与更新时间。
- 测试使用临时 SQLite，不污染正式数据。
- 存储层启用现有项目采用的 busy timeout，并保证连接正常关闭。

## 旧笔记功能删除

以下内容不迁移、不保留兼容入口，也不创建删除前备份：

- 删除整个 `plan/plugin/mashirobot-plugin-note`，包括 parser、storage、入口、清单、README 和全部测试。
- 从正式 SQLite 删除 `notes` 表及其索引；当前 2 条旧笔记随表删除，不导出到「战利品」。
- 删除专门为笔记功能创建的 `openclaw-planner-pre-note-*` 备份文件。
- 删除根 README、帮助菜单、健康检查、测试和其他活动文档中的旧笔记插件引用，改为「战利品」。
- 删除以旧笔记插件为主题的设计与实施计划文档；其他功能的历史文档若只是顺带提到插件清单，则只移除或改写该引用。
- 插件加载和健康检查结果中不得再出现 `mashirobot-plugin-note`、`添加笔记`、`查询笔记` 或 `删除笔记`。

包含其他业务数据的通用 SQLite 备份不整体删除，以免破坏英语统计、财报和作息等恢复点；它们不作为旧笔记功能的活动数据源。删除验收以正式数据库、专用笔记备份、运行时和活动代码/文档中不存在旧功能为准。

## 旧喝水与英语日志习惯下线

- 删除 Windows 计划任务 `OpenClaw-Daily-Water-1000`，使每天 10:00 不再发送喝水提醒。
- 删除旧 Windows 计划任务 `OpenClaw-Daily-EnglishJournal-2100`，避免其 21:00 提醒与「战利品」重复。
- 从计划插件路由中删除 `已喝水`、`已写日志`，并删除 `InstallFixed`、`SendHabit` 及 water/journal 固定提醒入口；不把它们迁入「战利品」插件。
- 从计划插件的普通帮助、详细帮助、帮助图片卡片数据和文字回退内容中，完整删除“喝水”“英语日志”“已喝水”“已写日志”及固定喝水/英语日志提醒的说明。
- 计划插件帮助中的睡觉、打卡、起床、睡眠查询、通用提醒、洗澡、夜间催促和磁盘空间说明保持不变。
- 历史 `habit_events` 数据留在正式数据库中但不再有用户入口；不为此次改造重建计划数据库。
- 除上述两项旧习惯和清理旧笔记引用外，不改动计划插件的其他作息、睡眠、起床和英语统计任务。

## 安装与运行

- 安装器把版本化运行副本复制到 `%LOCALAPPDATA%\MashiroBot\loot\runtime-v1`，计划任务只引用该稳定副本，不引用可能移动的工作区脚本。
- 安装器注册两个任务：晚间 21:00 至 22:00 每 10 分钟检查、次日 10:00 回放。
- 重复安装应更新运行副本和任务定义，不产生重复任务。
- 微信发送失败记录到插件日志并在下一次调度重试；22:00 后不为当晚失败额外创建催促任务。
- 电脑关机或无网络时不宣称消息已发送；任务恢复后遵守各自日期窗口，避免补发过期的晚间催促。

## 验收

1. `爽点` 后无正文时不写库；任意自由多行正文可成功保存并保留内部换行。
2. 同一天连续写入两次后，数据库和次日回放只包含第二次完整内容。
3. 不同日期的记录互不覆盖，所有日期按上海时区计算。
4. 21:00 至 22:00 无记录时按 10 分钟频率提醒；保存后当天余下检查全部静默；22:00 后不提醒。
5. 次日 10:00 有记录时按指定固定前缀和原文发送，无记录时静默。
6. `mashirobot-plugin-note` 目录、活动引用、命令、测试、专用备份和正式 `notes` 表全部不存在，旧 2 条笔记未迁移。
7. 菜单 4 加载「战利品」，插件路由和健康检查通过，其他插件菜单编号与行为不变。
8. `OpenClaw-Daily-Water-1000` 和 `OpenClaw-Daily-EnglishJournal-2100` 均不存在；其他无关计划任务保持原状。
9. 计划插件路由不再匹配 `已喝水` 或 `已写日志`；普通帮助、详细帮助、图片卡片和回退文本中搜索不到“喝水”“英语日志”“已喝水”或“已写日志”，截图中的两处旧说明不再出现。
10. worker 使用稳定运行副本，重复安装无重复任务，微信失败和过期运行均有可审计日志。
11. 完成单元测试、系统插件回归、计划任务定义检查、帮助图片渲染检查、网关重启和一次实际微信入口端到端验证。
