# 网站临时解除的 Clash DIRECT 覆盖设计

## 问题

网站临时解除已经从数据库、hosts 和浏览器策略中移除对应封禁，但 Clash 订阅自身可能仍包含该网站的 `REJECT` 规则。当前同步器只删除本工具写入的 `REJECT`，因此会出现机器人报告解除成功，而网站通过系统代理仍无法访问的情况。2026-10-06 的现场证据是：`zhihu.com` 直连可达，经 `127.0.0.1:7897` 的 Clash 代理则在 TLS 握手阶段失败。

## 目标

临时解除网站时，无论 Clash 订阅是否自带该网站的封禁规则，都应在解除期限内优先直连；到期或提前恢复禁止后，临时直连规则必须自动消失，原有禁止规则重新生效。

## 设计

### Clash 规则

- 对每个仍有效的临时解除域名，在本工具管理的最高优先级规则块中写入 `DOMAIN-SUFFIX,<domain>,DIRECT`。
- Bilibili 解除仍按现有逻辑展开到 `bilibili.com`、`bilivideo.com`、`hdslb.com` 和 `b23.tv`；普通网站只处理自身根域及子域。
- 临时解除域名不得同时出现在本工具生成的 `REJECT` 规则中。
- 到期、提前恢复或规则删除后，移除对应 `DIRECT`，再按仍生效的永久规则恢复 `REJECT`。
- 继续只修改持久化规则提供器及必要的生成配置，并沿用现有 Clash reload 流程；不关闭 Clash，不改订阅源，不影响其他代理规则。

### 其他封禁层

- hosts 和 Chrome/Edge 策略继续沿用现有临时解除逻辑。
- 数据库、分时额度、默认网站、机器人回复和到期调度语义保持不变。

### 失败处理

- 配置写入或 Clash reload 失败时，任务状态必须记录失败，机器人不得把系统同步失败描述为已完全解除。
- 周期 Reapply/Scan 会根据数据库中的当前解除状态重新生成规则，使中断后的状态可收敛。

## 测试与验收

1. 单元测试验证：解除域名生成优先 `DIRECT`，且没有同域 `REJECT`。
2. 到期或提前恢复后，`DIRECT` 被移除，永久规则重新生成 `REJECT`。
3. Bilibili 相关域名仍按现有展开规则处理。
4. 现有网站额度、数据库和 worker 回归测试全部通过。
5. 部署后真机验证：有效解除记录存在时，hosts 和浏览器策略无知乎封禁；Clash 持久化及运行配置含优先 `DIRECT`；通过系统代理访问 `https://www.zhihu.com/` 能完成 TLS/HTTP 响应。
6. 解除到期后验证 `DIRECT` 消失，知乎再次由永久规则禁止。

## 不在范围内

- 不停用或绕过整个 Clash。
- 不修改远程订阅内容。
- 不改变临时解除额度或持续时间。
- 不对没有临时解除记录的网站添加 `DIRECT`。
