# MashiroBot 项目速度与健壮性优化设计

## 目标

优化 `plan` 项目的公共消息链路以及下列插件，在保留现有指令、数据和用户可见语义的前提下，减少无意义等待、消除消息线程阻塞，并避免“回复成功但实际未生效”：

- `mashirobot-plugin-plan`
- `mashirobot-plugin-language`
- `mashirobot-plugin-status`
- `mashirobot-plugin-game-timer`（含 QQ、审计和禁止名单子模块）
- `mashirobot-plugin-loot`
- `plan/core`、帮助图片、健康检查及微信运行入口

`mashirobot-plugin-financial-report` 明确排除在本次优化之外。不得修改其源码、配置、测试、文档或运行行为；实施前后必须比较该目录的逐文件 SHA-256 清单。

## 当前证据

- 非财报范围当前共有 128 项 Node 测试，126 项通过、2 项跳过，总耗时约 11 秒。
- 插件契约强制 `match`、`handle`、`healthCheck` 和 `getHelp` 为同步函数；微信入口也同步调用路由。
- 计划和语言插件使用同步 Python/PowerShell 子进程；状态插件同步启动一次 PowerShell，并为状态图和温度图分别启动 Python。
- 游戏计时的 QQ 调度器使用 `Atomics.wait` 每 100 ms 轮询，最长可占用消息线程 5 分钟。
- “加入游戏”会为了刷新审计目标额外执行一次 QQ PowerShell 状态查询。现有测试中相关用例耗时约 2.3 至 5.8 秒，而其业务本身只需要写入本地配置。
- 多个模块各自实现超时、JSON 解析和错误截断，行为不一致，也缺少统一耗时记录。
- 现有路由已能在本地插件失败时阻止消息继续进入 GPT；该行为必须保留。

## 方案选择

采用“统一异步执行层并分插件迁移”。不采用只做局部缓存的方案，因为它会保留同步阻塞和重复错误处理；也不引入常驻 Python/PowerShell 服务，因为当前规模不足以抵消其部署、权限和恢复成本。

用户可见回复默认仍为一次最终回复。设计预留进度回调，但本次不启用“正在处理”与最终结果两段式消息。

## 总体架构

### 异步插件契约

- 微信 `process-message.js` 对快速路由使用 `await`。
- 核心路由接受插件函数直接返回结果或返回 Promise，兼容不需要迁移的同步函数。
- 插件加载器不再拒绝 `AsyncFunction`，但仍检查四个必需导出及返回结构。
- `match` 和 `getHelp` 保持快速、无外部副作用；耗时 I/O 只允许出现在 `handle` 或健康检查中。
- 每条消息生成请求编号，路由记录匹配插件、匹配耗时、处理耗时与结果类别。

### 公共本地执行器

在 `plan/core/execution` 建立一个边界清晰的执行模块，用 Node `spawn` 封装 Python、PowerShell 和普通可执行文件。调用方提供程序、参数、工作目录、环境变量白名单、超时和预期输出类型；执行器返回退出码、stdout、stderr、耗时和操作编号。

执行器必须：

- 不经过 shell 拼接命令；参数始终使用数组传递。
- 在超时时终止子进程树，并等待清理完成。
- 分别限制 stdout 与 stderr 大小，超限即终止，防止异常输出耗尽内存。
- 支持纯文本和 JSON；JSON 模式只接受完整 JSON 或明确允许的最后一条 JSON 行。
- 抛出带稳定错误码的错误：启动失败、超时、输出超限、非零退出、输出无效及结果未验证。
- 记录结构化耗时，但不记录聊天正文、账号数据或未脱敏参数。
- 支持依赖注入，使测试不启动真实 PowerShell、任务计划或桌面程序。

禁止在消息处理路径继续使用 `execFileSync`、`spawnSync`、`Atomics.wait` 或同步休眠。短时 SQLite 操作和小型本地文件读写可以继续同步执行。

### 真实结果验证

进程退出码只证明命令执行结束，不能单独作为业务成功依据。涉及 Windows 任务、QQ、游戏保护或计划保存的操作必须验证至少一种权威结果：

- 数据库事务提交后的目标记录；
- 原子状态文件中的操作编号、阶段和更新时间；
- 任务计划的存在、最近结果及对应状态文件；
- 目标进程、文件位置或保护记录。

写操作先创建待处理记录，验证成功后提交最终状态；失败或超时则回滚待处理状态和临时文件。状态不确定时回复“结果未确认”，不得回复成功。

## 插件设计

### 计划插件

- `planner-runner.mjs` 改用公共执行器，Python 与 PowerShell 调用全部异步。
- 查询、保存和图表继续使用现有 Python CLI，避免在本次重写业务规则。
- 检查 `manage-plan.ps1` 中重复的 Python 调用；能由一次 CLI 操作完成的数据写入合并为一次，Windows 任务注册保留在 PowerShell 边界。
- 保存回复前核验数据库记录；涉及提醒或唤醒时再核验任务与状态。数据库成功但任务失败时明确返回部分失败，不伪装成完整成功。
- 图表以命令类型、日期范围和规范化数据的哈希作为缓存键；数据变化才重新生成。

### 语言插件

- 删除自身重复的 Python 启动与 JSON 解析代码，复用计划插件暴露的规划器服务或公共执行器适配器。
- 查询文字统计与图表生成分层：统计成功、图表失败时仍返回文字，并附简短错误。
- 图表使用相同的内容哈希缓存策略。
- 关键词修改完成后核验配置文件和历史重算结果；任一步失败都不宣称已经完成重算。
- 新增独立解析、统计、缓存和故障降级测试。

### 状态插件

- PowerShell 采集器内部并行执行互不依赖的网络、温度、进程和磁盘探针。
- 一次 Python 调用可根据同一负载生成状态图与温度图，避免连续启动两次解释器。
- 实时状态采用数秒短缓存；硬件信息采用较长缓存。回复或图片数据包含实际采集时间，过期缓存不能冒充实时结果。
- 单个探针失败只影响对应字段；只有核心负载无法解析时才使整条指令失败。
- 缓存使用原子写入，并限制保留数量与总大小。

### 游戏计时插件

- “加入游戏”只更新游戏配置与审计清单，不再调用 QQ 状态。QQ 路径从已有审计目标或新鲜状态缓存读取。
- 普通游戏任务调度改用异步执行器；注册成功后核验任务名称与数据库状态。
- QQ `begin` 改为异步轮询原子状态文件，轮询期间让出事件循环；每次只接受匹配当前会话 ID 的新鲜状态。
- QQ 放行成功还必须满足启动文件已恢复、授权有效、桌面会话中的 QQ 进程已启动以及数据库进入 `playing`。
- 游戏强退、重点文件保护、禁止名单同步和 QQ 恢复均使用幂等操作编号。重复执行不重复移动文件，也不重复增加每日冷却次数。
- 失败统一撤销待处理锁；对已经产生的部分副作用执行安全恢复，并把恢复结果写入事件记录。

### 战利品插件

- 保留短时同步 SQLite 操作。
- 按规范化数据库路径复用存储实例，并确保表结构每个数据库只初始化一次。
- 继续使用 WAL 和 busy timeout；遇到忙锁时返回明确错误，不进行无上限重试。
- 进程关闭或测试结束时可靠关闭连接；连接失效时允许重建。

### 帮助、日志与健康检查

- 帮助图片仍按内容哈希缓存，缓存未命中时异步渲染；缓存命中不启动 Python。
- 日志字段包含请求编号、插件 ID、事件、总耗时、外部进程耗时、错误码和简短消息。
- 日志写入不得使插件执行失败；必要时改为排队写入或捕获写入异常。
- 健康检查区分“文件存在”“任务已注册”“执行器心跳新鲜”“业务结果已验证”，不能把任务注册成功等同于功能可用。
- 检查微信运行入口确实引用当前工作区核心文件，并在重启后核验新模块已加载。

## 数据流

1. 微信适配器收到消息并 `await` 核心路由。
2. 路由创建请求编号和上下文，按精确指令及插件优先级匹配。
3. 快速插件直接返回；需要外部程序的插件调用公共执行器。
4. 写操作创建待处理状态，执行系统操作，再读取权威状态验证。
5. 插件返回规范结果；路由记录耗时并交给微信发送文字和媒体。
6. 任一步失败都转换为本地、可读且不误导的错误，不继续进入 GPT。

## 并发与一致性

- 同一资源的写操作使用数据库唯一约束、事务或操作锁串行化；不同插件和不同资源可以并发。
- 缓存写入采用临时文件加原子替换，读者永远只能看到旧的完整文件或新的完整文件。
- 轮询必须有截止时间、取消信号和状态新鲜度判断。
- 路由不得因一个插件的长操作阻止另一条消息进入事件循环。
- 重复消息、网关重启和后台任务重放都必须保持幂等。

## 性能目标

- `查看游戏`、`查看游戏计时`、战利品保存等纯本地路径在测试环境中低于 100 ms。
- “加入游戏”不启动 PowerShell，目标低于 200 ms；当前约 2.3 至 5.8 秒的无关 QQ 查询必须消失。
- 相同帮助页、统计图和硬件图命中缓存时不启动 Python。
- 冷状态采集可以持续数秒，但不得阻塞其他消息；短期重复查询走新鲜缓存。
- 消息处理事件循环不出现由同步外部进程或轮询造成的 100 ms 以上停顿。
- 所有外部操作使用有界超时；超时后不残留子进程、待处理锁或临时文件。

这些目标只覆盖本地处理时间，不包含微信网络发送耗时。

## 测试与验收

### 自动测试

- 保留现有非财报测试及用户可见语义。
- 为异步路由增加同步插件兼容、异步结果、并发消息和本地错误短路测试。
- 为公共执行器增加启动失败、超时、进程树清理、输出超限、非零退出、无效 JSON 和取消测试。
- 为状态插件增加短缓存、长缓存、单次双图渲染、部分探针失败和过期数据测试。
- 为游戏计时增加“加入游戏不查询 QQ”、QQ 轮询不阻塞、状态串话拒绝、假成功拒绝、回滚与幂等测试。
- 为计划与语言增加统计缓存、数据库成功但任务失败、图表失败文字保留和关键词重算验证测试。
- 为战利品增加连接复用、忙锁和连接恢复测试。

### 实机验证

在不会破坏现有数据的前提下，验证帮助、只读计划查询、英语统计、状态、加入/查看测试游戏、临时数据库游戏计时和临时数据库战利品记录。涉及正式 QQ、正式游戏进程或真实提醒的破坏性动作不自动触发，除非用户另外明确要求。

验证运行入口、网关健康、后台执行器心跳和日志中的版本/请求编号。测试通过但运行入口仍加载旧模块时，项目不得判定完成。

### 性能对比

记录优化前后相同命令的中位耗时、最大耗时和外部进程启动次数。至少覆盖帮助缓存命中、英语统计缓存命中/未命中、状态缓存命中/未命中、加入游戏、查看游戏和战利品保存。

### 排除目录保护

实施前生成 `mashirobot-plugin-financial-report` 目录逐文件相对路径、大小和 SHA-256 清单；实施后重新生成并逐项比较。不得通过更新其快照或忽略差异使检查通过。

## 部署与回滚

1. 先完成公共异步契约和执行器，并用模拟插件验证兼容性。
2. 按状态、语言、计划、游戏计时、战利品顺序迁移，每个阶段运行全套非财报测试。
3. 修复并核验微信适配器后重启网关，确认实际运行入口已加载新版本。
4. 保留改动前适配器备份；若新入口无法处理消息，恢复适配器并重启网关。
5. 数据库迁移必须向后兼容；本次不删除现有业务表或用户数据。

## 完成条件

只有同时满足下列条件才能宣布完成：

- 所有列入范围的同步外部进程和阻塞轮询已从消息链移除。
- 各插件上述优化与错误处理均已实现。
- 非财报测试全部通过，新增故障测试和并发测试通过。
- 实机运行入口、网关和安全的代表性命令已验证。
- 性能对比达到目标，或对未达到项给出可复现证据和明确剩余限制。
- 财报插件目录哈希清单与实施前完全一致。
