# 财报课程多行微信发送修复设计

## 目标

修复财报课程卡经微信发送后只剩第一行标题的问题。采用用户批准的推荐呈现方式：完整分段文字加官方原文链接，不改成图片卡片，也不附整份 PDF。

## 已确认原因

课程生成器已经产生完整内容，包含课程标题、预计时间、学习目标、阅读范围、财报事实、通俗解释、常见误区、今日问题和官方原文链接。截断发生在 Windows 发送边界：PowerShell 将含换行的 `--message` 参数交给 `openclaw.cmd`，CMD 对多行参数处理不可靠，只把第一行传给微信。

项目现有开发规范明确要求微信发送直接调用 `openclaw.ps1`，不能依赖 `openclaw.cmd` 传递中文多行内容。

## 设计

1. `windows/common.ps1` 增加固定的 `openclaw.ps1` 路径，普通微信消息发送改用该入口。
2. OpenClaw 聊天点评继续使用 `openclaw.cmd agent --message-file`。它通过 UTF-8 文件传入提示词，不经过多行命令行参数，因此不属于本次故障范围。
3. 课程内容、SQLite 幂等键和自动发送时间保持不变。
4. 修复安装到版本化 `runtime-v1` 后，手动重新发送今天的完整第一课；这次补发不新增或重置自动发送记录。

## 错误处理与隐私

- 找不到 `openclaw.ps1` 时明确失败，不回退到可能截断内容的 `.cmd`。
- 仍只在 OpenClaw 返回成功后记录发送成功。
- 日志不记录完整课程卡、用户答案或点评提示词。

## 验证

1. 静态测试断言普通微信发送使用 `openclaw.ps1`，且不使用 `openclaw.cmd message send`。
2. 隔离测试传入含中文、换行和官方 URL 的课程卡，确认完整内容到达模拟发送边界。
3. 运行系统与插件全部回归测试并重新安装 `runtime-v1`。
4. 重新发送第一课，核对微信侧至少出现以下段落：`【财报事实】`、`【通俗解释】`、`【常见误区】`、`【今日问题】`、`【官方原文】`。
5. 正式数据库中今天第 1 课仍只有一条自动发送记录，状态为 `sent`。

## 非目标

- 不制作图片课程卡。
- 不下载或发送整份年报附件。
- 不修改聊天模式点评、课程内容、课程日历或招股书安排。
